# EXPLAINABILITY — agentUniverse

## How the Agent Decides

agentUniverse orchestrates domain-expert multi-agent systems using structured collaboration patterns (such as PEER and DOE) designed to tackle complex analytical reasoning and data-intensive tasks. Inquiries flow through five deterministic processing stages:

```
[ User Inquiry & Task Ingestion ]
                │
                ▼
[ 1. Pattern Selection & Domain Routing ]
                │
                ▼
[ 2. Task Decomposition (Planner / Data-fining) ]
                │
                ▼
[ 3. Domain RAG & Execution (Executor / Opinion-inject) ]
                │
                ▼
[ 4. Synthesis & Peer Review (Expresser / Reviewer) ]
                │
                ▼
[ 5. Delivery & Session Trace Archiving ]
```

### 1. Mathematical Scoring & Routing Formulation
During the Review stage of the PEER pattern, the Reviewer agent calculates an objective quality evaluation score $S_{\text{eval}}$ to decide whether the drafted analysis is ready for delivery or requires a refinement loop:

$$S_{\text{eval}} = w_c \cdot C_{\text{completeness}} + w_a \cdot A_{\text{factual}} + w_r \cdot R_{\text{reasoning}} + w_d \cdot D_{\text{domain}}$$

Where:
- $C_{\text{completeness}} \in [0, 1]$: Measure of whether all subtasks generated by the Planner were addressed.
- $A_{\text{factual}} \in [0, 1]$: Source citation density and factual consistency against retrieved domain passages.
- $R_{\text{reasoning}} \in [0, 1]$: Logical consistency and depth of deduction in the intermediate arguments.
- $D_{\text{domain}} \in [0, 1]$: Alignment with specialized institutional guidelines and terminology rubrics.
- Weights: $w_c = 0.25$, $w_a = 0.35$, $w_r = 0.25$, $w_d = 0.15$ ($\sum w_i = 1.0$).

Output delivery is approved if $S_{\text{eval}} \ge \tau_{\text{quality}} = 0.80$. If $S_{\text{eval}} < 0.80$ and current iteration count $k < K_{\text{max}} = 3$, the workflow re-enters the execution loop with targeted critique feedback.

### 2. Refusal Criteria & Decision Thresholds
agentUniverse enforces deterministic refusal boundaries across its execution patterns:

| Trigger Scenario | Operational Action | Error Code |
| :--- | :--- | :--- |
| Quality score fails threshold ($S_{\text{eval}} < 0.80$) and $k \ge 3$ loops | Terminate loop; return best-effort draft with prominent confidence warnings | `ERR_MAX_LOOPS_EXCEEDED` |
| Numerical discrepancy detected between source data tables and narrative | Halt expresser synthesis; require data recalculation | `ERR_NUMERICAL_DISCREPANCY` |
| Domain knowledge retrieval returns relevance score below minimum cutoff ($< 0.60$) | Flag missing domain reference; solicit supplementary context from user | `ERR_DOMAIN_KNOWLEDGE_MISSING` |
| Attempted execution of unapproved external API or unverified tool | Reject tool invocation; log unauthorized dispatch attempt | `ERR_UNAUTHORIZED_TOOL_DISPATCH` |
| LLM vendor endpoint latency exceeds threshold (> 45s) | Switch to secondary configured model backend | `ERR_LLM_GATEWAY_TIMEOUT` |

### 3. Multi-Tier Fallback Mechanisms
1. **Multi-Model Fallback**: If the primary foundation model (e.g., DeepSeek-R1 or Qwen-2.5) encounters service rate limits, the framework dynamically re-routes agent prompts to configured backup providers (e.g., OpenAI or Claude).
2. **Review Loop Fallback**: When review cycles hit the maximum ceiling ($k = 3$) without reaching the target score, the framework packages the reviewer's diagnostic feedback alongside the output rather than failing silently.
3. **Retrieval Degradation**: If vector databases (ChromaDB/Milvus) are temporarily unavailable, the RAG skill degrades to local keyword searches and cached document summaries.

### 4. Human-in-the-Loop Governance
- **High-Stakes Decision Sign-Off**: Financial filings, portfolio recommendations, and public announcements require explicit human confirmation before external delivery.
- **Pattern Configuration Auditing**: Modifying agent prompts, temperature settings, and tool whitelists in production requires administrator privileges.
- **Visual Trace Inspection**: Business analysts can review multi-agent conversation logs, planning DAGs, and evaluation scores using the agentUniverse visual platform.

## The Data It Uses

### 1. Input Data Types
- **User Task Prompts**: Analytical requests, research inquiries, event interpretation goals, and financial reporting parameters.
- **Enterprise Datasets**: Raw quantitative tables, balance sheets, trading feeds, and time-series metrics.
- **Domain Literature**: Industry research reports, corporate regulatory filings (10-K, 10-Q), and compliance documentation.

### 2. Reference & Configuration Data
- **Domain Knowledge Embeddings**: Chunked passages and dense vector representations indexed in ChromaDB or Milvus.
- **Pattern Component Definitions**: Declarative YAML configurations defining agent roles, prompt templates, and orchestration rules (PEER, DOE).
- **Tool Registries**: OpenAPI specifications and execution wrappers for financial calculators, search engines, and database connectors.

### 3. Model Lineage & System Architecture
- **Supported Foundation Models**: Multi-vendor compatibility including Qwen series, DeepSeek (V3/R1), OpenAI (o1/o3/GPT-4o), Claude 3.7/3.5, and Gemini 2.5/2.0.
- **Component Engine**: Python 3.10+ runtime leveraging LangChain components, Pydantic data validation, and SQLAlchemy storage.
- **Trace Logger**: Comprehensive Loguru-based execution auditing tracing inter-agent message exchanges and token expenditures.

### 4. Data Privacy, Retention & Sanitization
- **API Key Segregation**: Credentials are kept strictly isolated in `custom_key.toml` or environment variables; never persisted in logs or database tables.
- **Session Data Isolation**: Working memory and blackboard artifacts are scoped by session ID and purged upon task completion.
- **No Third-Party Exfiltration**: Local deployments ensure that raw financial inputs are dispatched only to enterprise-approved LLM gateways.

## Limitations

### 1. Multi-Agent Token Consumption
- **Limitation**: Running multi-agent patterns (PEER with review loops) consumes significantly more tokens than single-turn inference.
- **Mitigation**: Implement context compression between stages and set strict iteration caps ($K_{\text{max}} = 3$) on review cycles.

### 2. Numerical Hallucination in Complex Financial Formulas
- **Limitation**: LLMs may introduce slight arithmetic inaccuracies when calculating compound growth rates or ratios directly.
- **Mitigation**: Utilize the DOE pattern's Data-fining agent to execute calculations strictly via Python code sandbox tools rather than LLM token generation.

### 3. Asynchronous Execution Latency
- **Limitation**: Sequential multi-agent handoffs introduce end-to-end latency that may be unsuitable for sub-second real-time queries.
- **Mitigation**: Enable streaming responses for intermediate steps and execute independent subtasks concurrently via asynchronous worker pools.

### 4. Knowledge Base Freshness
- **Limitation**: Pre-indexed vector embeddings cannot reflect breaking intraday market news without live ingestion.
- **Mitigation**: Pair vector RAG with real-time web search tool integrations to fetch breaking news updates dynamically.

### 5. Reviewer Agent Bias
- **Limitation**: A Reviewer agent powered by the same foundation model as the Executor may exhibit self-agreement bias.
- **Mitigation**: Configure heterogeneous models (e.g., DeepSeek-R1 for reasoning and Claude 3.5 Sonnet for reviewing) to introduce independent evaluation perspectives.
