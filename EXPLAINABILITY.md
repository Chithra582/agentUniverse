## How the Agent Decides

agentUniverse orchestrates domain-expert multi-agent systems using structured collaboration patterns (such as PEER and DOE) designed to tackle complex analytical reasoning and data-intensive tasks. Inquiries flow through a deterministic five-stage decision architecture:

### 1. Decision Architecture

The runtime inquiry intake, task decomposition, agent dispatch, and peer evaluation operate across a deterministic, five-stage pipeline:

```
[ User Inquiry & Task Ingestion ]
                │
                ▼
[Stage 1: Pattern Selection & Domain Routing Gate]
  - Analyzes problem complexity and task taxonomy
  - Selects orchestration pattern (PEER: Plan-Execute-Express-Review, or DOE)
  - Identifies domain boundary and required expert persona agents
                ▼
[Stage 2: Task Decomposition & Planning Gate (Planner / Data-fining)]
  - Deconstructs high-level goal into dependency-ordered DAG of subtasks
  - Allocates token and context budgets per subtask
  - Assigns specialized agent roles (planner, executor, critic)
                ▼
[Stage 3: Domain RAG & Execution Gate (Executor / Opinion-inject)]
  - Executes parallel domain vector retrieval (Milvus/ChromaDB)
  - Runs intermediate agent inference and tool dispatches
  - Synthesizes domain knowledge into structured intermediate evidence
                ▼
[Stage 4: Synthesis & Peer Review Gate (Expresser / Reviewer)]
  - Expresser aggregates intermediate outputs into unified cohesive draft
  - Reviewer executes multi-criteria evaluation scoring S_eval
  - Checks factual consistency, reasoning validity, and guideline compliance
                ▼
[Stage 5: Delivery & Session Trace Archiving Gate]
  - If S_eval >= tau_quality, approves delivery to caller
  - If S_eval < tau_quality and loops < K_max, routes targeted critique back to Stage 3
  - Archives full decision DAG, reasoning traces, and audit telemetry
                ▼
[ Verified Multi-Agent Synthesis Delivered ]
```

### 2. Decision Logic & Routing Formulations

During the Review stage of the PEER pattern, the Reviewer agent calculates two objective, mathematically rigorous evaluation formulations:

1. **Review Quality & Completeness Score ($S_{\text{eval}}$)**:
   $$S_{\text{eval}} = w_c \cdot C_{\text{completeness}} + w_a \cdot A_{\text{factual}} + w_r \cdot R_{\text{reasoning}} + w_d \cdot D_{\text{domain}}$$
   where:
   - $C_{\text{completeness}} \in [0, 1]$: Measure of whether all subtasks generated by the Planner were addressed.
   - $A_{\text{factual}} \in [0, 1]$: Source citation density and factual consistency against retrieved domain passages.
   - $R_{\text{reasoning}} \in [0, 1]$: Logical consistency and depth of deduction in the intermediate arguments.
   - $D_{\text{domain}} \in [0, 1]$: Alignment with specialized institutional guidelines and terminology rubrics.
   - Weights: $w_c = 0.25$, $w_a = 0.35$, $w_r = 0.25$, $w_d = 0.15$ ($\sum w_i = 1.0$).
   - Output delivery is approved if $S_{\text{eval}} \ge \tau_{\text{quality}} = 0.80$.

2. **Domain Alignment & Confidence Index ($I_{\text{confidence}}$)**:
   $$I_{\text{confidence}} = \left(w_s \cdot S_{\text{semantic}}\right) + \left(w_v \cdot V_{\text{validation}}\right) + \left(w_u \cdot (1 - U_{\text{uncertainty}})\right)$$
   where:
   - $S_{\text{semantic}} \in [0, 1]$: Cosine similarity between expert outputs and verified domain ground-truth embeddings.
   - $V_{\text{validation}} \in [0, 1]$: Ratio of automated schema validation checks successfully cleared.
   - $U_{\text{uncertainty}} \in [0, 1]$: Entropy-based uncertainty measure across token probability distributions.
   - Weights: $w_s = 0.40$, $w_v = 0.35$, $w_u = 0.25$. Delivery requires $I_{\text{confidence}} \ge 0.75$.

### 3. Thresholding & Refusal Decision Criteria

agentUniverse deterministically refuses requests that violate financial safety or execution boundaries:
- **Refusal on Max Loop Exhaustion**: Workflows failing quality cutoff ($S_{\text{eval}} < 0.80$) after 3 review cycles terminate with code `ERR_MAX_LOOPS_EXCEEDED`.
- **Refusal on Numerical Discrepancy**: Synthesized narratives with numbers contradictory to source financial tables halt with code `ERR_NUMERICAL_DISCREPANCY`.
- **Refusal on Sub-Threshold Passage Relevance**: Knowledge queries returning relevance scores below cutoff ($< 0.60$) are rejected with code `ERR_DOMAIN_KNOWLEDGE_MISSING`.
- **Refusal on Unauthorized Tool Dispatch**: Invocations of unregistered or external APIs outside whitelist permissions are blocked with code `ERR_UNAUTHORIZED_TOOL_DISPATCH`.
- **Refusal on Gateway Latency Timeout**: Upstream model calls exceeding the 45-second budget trigger refuse/failover with code `ERR_LLM_GATEWAY_TIMEOUT`.

### 4. Fallback Decision Mechanism

agentUniverse maintains operational resilience through layered fallback mechanisms:
- **Multi-Model Provider Fallback**: If primary foundation models (DeepSeek-R1 / Qwen-2.5) experience rate limits or outages, prompts dynamically fail over to secondary configured endpoints (OpenAI / Claude).
- **Review Loop Graceful Degradation**: When review cycles hit the maximum ceiling without reaching target score, the agent delivers the draft annotated with reviewer diagnostics rather than failing silently.
- **Local Lexical Search Fallback**: If vector databases (ChromaDB / Milvus) encounter network timeouts, retrieval degrades to local BM25 keyword matching over cached documents.
- **Model Fallback Cascade**: High-level multi-agent synthesis tasks default to `gemini-2.0-flash` with automatic failover to `gpt-4o` and `claude-3-5-sonnet`.

### 5. Human-in-the-Loop Governance

Human operators retain sovereign authority over the multi-agent execution lifecycle:
- **High-Stakes Decision Sign-Off**: Financial filings, portfolio recommendations, and public announcements require explicit human confirmation before external delivery.
- **Pattern Configuration Auditing**: Modifying agent prompts, temperature settings, and tool whitelists in production requires administrator privileges.
- **Visual Trace Inspection**: Business analysts can review multi-agent conversation logs, planning DAGs, and evaluation scores using the agentUniverse visual platform.

## The Data It Uses

agentUniverse operates under strict principles of data minimization, local environment isolation, and developer privacy.

### 1. Ingested Input Data

- **Analytical Inquiries**: Complex financial questions, market research prompts, and enterprise analytical instructions.
- **Unstructured Documents**: PDF financial statements, earnings call transcripts, news articles, and SEC filings.
- **Structured Data Tables**: Financial time series, balance sheets, macroeconomic indicators, and relational database records.

### 2. Configuration & Reference Data

- **Pattern Configuration YAMLs**: Declarative definitions for PEER, DOE, and custom multi-agent routing topologies.
- **Domain Ontologies & Prompt Templates**: Specialized finance prompt definitions, metric formulas, and critique rubrics.
- **Agent Role & Tool Registries**: Skill definitions, permission profiles, API configurations, and vector collection metadata.

### 3. Base Model & Inference Lineage

- **Reasoning Models**: DeepSeek-R1, Qwen-2.5-72B-Instruct, Claude-3.5-Sonnet, GPT-4o for complex multi-agent planning and critique.
- **Embedding Models**: BAAI/bge-large-zh-v1.5, text-embedding-3-large for high-fidelity financial document retrieval.
- **Orchestration Runtime**: Python 3.10+ asynchronous runtime with gRPC/REST APIs and Celery task execution queues.

### 4. Data Privacy, Storage, and Retention

- **OWASP LLM & MITRE ATLAS Hardened**: Defended against indirect prompt injection in retrieved domain passages, adversarial financial data manipulation, and unauthorized external API dispatch.
- **Enterprise Tenant Isolation**: Memory stores, vector partitions, and execution traces reside strictly within designated local or VPC-isolated database instances.
- **Automated Secret Scrubbing**: API keys, database credentials, and customer personal account numbers are automatically masked and redacted prior to embedding or logging.
- **Zero Commercial Monetization**: Financial queries, document excerpts, and agent reasoning traces are never commercialized, aggregated, or shared with third parties.

## Limitations

Understanding the operational boundaries and technical constraints of agentUniverse is essential for effective deployment.

### 1. Multi-Agent Reasoning Latency
- **Limitation**: Orchestrating sequential multi-agent review cycles (PEER) introduces latency (15–60s) compared to single-prompt LLM generation.
- **Mitigation**: Parallelize subtask execution across independent agent workers and implement early-exit criteria when preliminary review score exceeds 0.90.

### 2. Domain Knowledge Freshness
- **Limitation**: Offline vector indices do not capture intraday real-time market data movements without continuous re-indexing pipelines.
- **Mitigation**: Provide real-time financial API integration tools to query live order books and ticker feeds dynamically.

### 3. Hallucination in Ambiguous Edge Cases
- **Limitation**: When confronted with incomplete or conflicting financial filings, individual reasoning agents may hallucinate reconciliations.
- **Mitigation**: The dedicated Reviewer agent enforces factual consistency checks against raw cited excerpts with refusal thresholds.

### 4. Computational Resource Consumption
- **Limitation**: Multi-agent loops consume significantly higher token quotas per query compared to conventional chatbots.
- **Mitigation**: Enforce per-session token budget ceilings ($T_{\text{budget}} \le 16,000$ tokens) and automatic compression of intermediate agent dialogs.

### 5. Cross-Lingual Financial Nuance
- **Limitation**: Specialized financial jargon and regulatory terminologies (e.g., Chinese GAAP vs US GAAP) can lead to subtle semantic drift during translation.
- **Mitigation**: Deploy specialized dual-language prompt rubrics and verified multilingual financial embedding models.
